Key Concepts:

🚧 Challenges We Faced (& Solved!)

Challenge Problem Our Solution
💡 Poor Lighting Recognition accuracy dropped to 60% in dim conditions Added image preprocessing, recommended good lighting in guidelines
👥 Multiple Faces Sometimes detected wrong person or missed faces Improved matching algorithm, adjusted tolerance parameter to 0.6
📱 Camera Access Different browsers had different camera APIs Used HTML5 getUserMedia() with fallback to file upload
☁️ Deployment Needed public URL for demo but no server Used Google Colab + ngrok for free cloud deployment
🔄 Data Conflicts Multiple captures could override "Present" with "Absent" Smart update logic: never overwrite Present → Absent

Key Learning: Every problem has a solution - persistence and creative thinking are essential! 💪

💻 Technical Details (Bonus)

For those interested in the code...

Face Recognition Algorithm

  • Uses dlib's HOG (Histogram of Oriented Gradients) for face detection
  • ResNet-based deep learning model for face encoding (128-dimensional vectors)
  • Euclidean distance calculation for matching (threshold: 0.6)
  • Processing time: ~1-2 seconds per image on Colab

Key Code Components

  • load_known_faces() - Loads and encodes student photos from CSV
  • run_attendance() - Processes test image and identifies students
  • update_attendance_csv() - Updates database with smart logic
  • /upload API endpoint - Handles image upload and processing

Data Flow

  1. User captures/uploads image → Browser sends to Flask server
  2. Flask saves temporarily with UUID-based filename
  3. Face recognition module processes image
  4. Results returned as JSON with base64-encoded image
  5. CSV database updated with new attendance data
  6. Frontend displays results with color-coded status
